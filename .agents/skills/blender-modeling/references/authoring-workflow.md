# アセット作成ワークフロー

## 1. 要件を形状と外観に分ける

- 形状: 部品、輪郭、寸法、厚み、接続、原点、配置
- 外観: 色、Material、Texture、粗さなど、必要とされる見た目
- 出力: 用途、形式、単位、座標系、出力先

曖昧な要件や対象アプリ固有の条件は、確定事項と仮定を分けて扱う。

## 2. Sceneと編集範囲を決める

- 既存SceneやObjectの状態を先に確認する。
- 意味のあるObject名・Collection名を付け、関係のある要素をまとめる。
- 既存データを残す必要がある場合は、編集前に複製または別名保存を検討する。
- 不要データの削除は、対象を特定し、必要なら承認を得てから行う。

## 3. モデルを作成する

- まず必要な大きさ・シルエット・部品構成を満たす。
- ポリゴン数や細部の密度は、用途と性能要件に合わせる。根拠のない一律の上限を設けない。
- 法線、面の重なり、穴、非多様体などは、用途に応じて確認する。
- 床・壁・天井・トンネル・家具などの基礎形状を装飾より先に接合する。設計寸法とワールド空間の境界を照合し、継ぎ目の視認できる隙間や食い違いを残さない。
- 箱状部材の角は、幅と位置から接触面を計算し、端面同士が一致するようにする。隠れる箇所を重ねる設計では、内部面の重複が表示や衝突に影響しないことを確認する。
- 装飾ネオンは基礎形状の接合確認後に配置する。直交するネオン同士は外形寸法で端点を合わせ、意図しない体積の重なりや同一平面の表示面を作らない。表示面との距離は一律の隙間にせず、視認できる継ぎ目を作らない範囲でちらつきを避けるよう調整する。
- 接合や見え方を保てない場合は、ネオンや装飾を省略・後回しにし、基礎形状の連続性を優先する。
- 原点、回転、スケールを確認し、適用変換が必要かどうかは出力先の要件に基づいて決める。

### 再利用できる壁の開口

- 壁に通路を設ける場合は、壁全体を一体の編集困難なメッシュにせず、左右の壁・まぐさ等の部材に分けるか、開口用カッターと未適用のBoolean Modifierを保持した`.blend`を編集元として保存する。FBX用データは編集元から作り、編集可能な形状と出力用メッシュを区別する。
- 開口の幅・高さ・厚み・中心位置を寸法で決め、プレイヤーの実際の当たり判定と移動方向に必要な余裕を照合する。Unity側では表示メッシュとColliderを別に確認し、入口から出口までの移動範囲に残るColliderや隣接壁も検査する。
- 既存アセットの生成元を特定してから編集する。Unityの`.asset` MeshはBlenderの`.blend`やFBXとは限らないため、シリアライズデータを直接編集せず、編集元または生成手順から新しいメッシュを作り、元アセットを保持してUnityで再確認する。
- このリポジトリ付属のBlender MCPは新規のプリミティブScene作成用で、既存SceneやObjectの編集、カスタムメッシュ、Boolean操作には対応しない。これらが必要な作業では、利用可能なBlender編集手段を確認し、MCPが未対応の操作を実行済みと扱わない。

## 4. 外観とデータを整える

- Material、UV、Textureは必要な場合に作成・確認する。
- 使用していないデータを整理するときは、他のObjectから参照されていないことを確認する。
- テクスチャ形式や解像度は、出力先の要件を確認して決める。

## 5. 確認して受け渡す

- [検証チェックリスト](./validation-checklist.md)を用途に応じて使う。
- エクスポート設定は対象形式・受け取り側の仕様に基づいて決める。
- Unity向けFBXでは、[Blender MCP設定資料](./mcp-configuration.md)に記録した単位・変換・軸設定と、その適用範囲を確認する。
- Blender内の確認と、外部アプリでのインポート確認を区別して報告する。
