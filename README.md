# secret-base-world

Cluster向けワールド制作のための開発拠点です。UnityとBlenderのMCP構成、制作Skill、汎用的な制作・検証手順をまとめています。

## 方針

- Unityプロジェクトは `UnityProject/` にあります。Unityを開く前に[開発環境ガイド](./docs/development-setup.md)に従いサブモジュールを初期化してください。
- `UnityProject/` にはCluster Creator Kitの公式テンプレートとサンプルシーンが含まれます。テンプレートの`LICENSE.md`と`README.md`も保持してください。
- `.mcp.json` はUnityプロジェクトが `UnityProject/` にある構成を想定しています。
- リポジトリ全体のライセンスは未設定です。`UnityProject/` 内のテンプレート部分とroom由来の機能には、各配布元の [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) が適用されます。サブモジュールにはそれぞれの利用条件が適用されます。

## 開発環境

- Unity Editor / Cluster Creator Kit: 利用するテンプレートとCCKが要求するバージョン
- Unity CLI: Unity Editor連携MCP用
- Node.js: 20以上（SceneGraph解析器は26.x）
- Blender: FBX Export APIを利用できるバージョン

セットアップの詳細は[開発環境ガイド](./docs/development-setup.md)を参照してください。

## 含まれるもの

- `.agents/skills/`: Clusterワールド、Blender、ClusterScript向けのAgent Skills
- `.github/instructions/`: Unity描画設定とConsole検証の共通指示
- `UnityProject/`: Cluster Creator Kitテンプレートプロジェクトとサンプルシーン
- `scripts/blender-mcp.mjs`: 基本形状から `.blend` と `.fbx` を生成するBlender MCPサーバー
- `scripts/setup-cluster-template.ps1`: 初回用テンプレート取得・配置スクリプト
- `tools/cck-scenegraph-tools/`: SceneGraph Exporter、解析器とClusterScript関連Skillの固定参照
- `tools/blender-modeling-tools/`: Blender Skillと技術資料の固定参照
- `.mcp.json`: UnityとBlenderのMCP接続設定

Blender MCPは新しいシーンを基本形状から生成するもので、既存のBlenderシーンを編集するツールではありません。

## 神殿の背景

`SpinRoutePrototype` はBuilt-inの `Skybox/Panoramic` と静止した全天画像を使用します。浮遊島・水鏡・雲海は背景画像であり、地形やリアルタイム反射ではありません。画像の生成元は `UnityProject/AgentScripts/DreamTempleSky.cs` です。Unity Editorを開いた状態でUnity MCPの `run_script` に `AgentScripts/DreamTempleSky.cs` とエントリーポイント `DreamTempleSky.Generate` を指定すると、追跡対象の `DreamTempleSky.png` を上書き生成します。既存の `.meta` とマテリアルの参照は維持してください。

全天画像は縦の継ぎ目を防ぐため、横方向のRepeatを有効にし、ミップマップを無効にしています。

## Spinの分岐

`SpinRoutePrototype` の入口 `(0, -2)` は約5.2×5m、壁高3mの石壁と天井で囲み、正面の正規Start `(0, -1)` または左の寄り道Start `(-2, -1)` を通って出る構成です。外周から戻る通路には入口へ向かうStart `(2, -4)` があります。ゴールには約5×5mの余白を確保しています。

停止後の徒歩による迂回を防ぐため、移動区間も石壁で区切っています。壁には高さ0.9mの横長の開口を設け、景色が見えるようにしています。開口部には透明なColliderを置かず、上下の石部分にColliderを合わせています。
両階の迷路壁は床との面重なりを避けるため、表示とColliderを一緒に0.01m下げています。

寄り道は、単にキューブを増やすのではなく、正規ルートとの位置関係や停止後の選択に役割を持たせています。座標は `(x, z)`、方向はSpinの移動方向です。

| 場所・入口 | 寄り道の意図と想定経路 |
| --- | --- |
| 上階・入口 `(-2, -1)` +Z | 正規Start `(0, -1)` と同方向だが、左を選ぶと `(-2, 5)` で停止。歩いて `(-1, 9)` +X、`(8, 6)` -Z と進み、`(8, 1)` で停止する。 |
| 上階・入口側 `(8, -1)` -Z | 上記の停止後、外周方向に進み南の外周Stopで停止。回廊を歩いて `(2, -4)` -X に入り、`(-1, -4)` で停止して入口に戻る。 |
| 上階・曲がり角 `(2, 4)` +X | 正規Start `(2, 6)` と同方向だが、`(6, 4)` で停止。`(6, 2)` -X と `(2, 2)` のStopを経て、入口側の移動床から選択室に戻る。 |
| 1階 `(8, 8)` +X | 正規Start `(8, 6)` の隣の平行ルート。`(14, 8)` で停止し、`(14, 10)` -X と `(8, 10)` のStopを経て選択室に戻る。 |
| 1階 `(8, 4)` +X | 正規Startを挟んだ反対側の平行ルート。`(14, 4)` で停止し、`(14, 2)` -X と `(4, 2)` のStopを経て選択室に戻る。 |
| 1階 `(4, 6)` -X | 正規の東向きとは逆に西へ出て、北・東・南・西と床の広い範囲を巡る長い寄り道。`(-1, 6)`、`(-1, 22)`、`(21, 22)`、`(21, 12)`、`(1, 12)`、`(1, 8)` の各Stopを経て、`(3, 8)` +X で選択室へ戻る。 |
| 1階・北側区画 `(3, 12)` +Z | `(1, 12)` のStopから歩いて入り、境界壁の開口を通る。`(3, 14)` から `(5, 14)` +X、`(10, 14)` から `(10, 16)` +Z、`(10, 20)` から `(18, 20)` -Z、`(18, 18)` から `(12, 18)` -Z、`(12, 15)` から `(17, 15)` -Z と進み、`(17, 12)` で既存ルートへ戻る。北側の未使用床を巡る長い迂回路。 |
| 上階・ゴール手前 `(17, 12)` +Z | 正規Start `(19, 12)` と同方向だが、`(17, 14)` で早く停止。`(15, 14)` -Z と `(15, 8)` のStopを経て選択室に戻る。 |
| 上階・外側 `(21, 11)` +Z | ゴール手前の選択室から外側へ向かい、`(21, 16)` で停止。`(23, 16)` -Z、`(23, 12)` のStop、`(24, 11)` -Z、`(24, 8)` のStop、`(22, 8)` -X を経て選択室に戻る。最後のSpinは戻り道への逆進入も押し戻す。 |
| 上階・ゴール正規ルート `(19,19)` +X | `(19,18)` のStopから1歩北へ進んでStartに触れ、`(22,19)` で停止。`(22,20)` +Z から `(22,22)` まで進み、北の `(22,23)` -X から `(19,23)` で停止する。南へ1歩戻ると金色の祭壇門がある `(19,22)` のゴールに着く。 |
| 上階・試作回廊 `(22, 23)` -X | ゴール手前のStopから北へ歩いて入り、`(19, 23)` で停止。南のゴールへ戻らず東の `(20, 23)` +Z を選ぶと、北端のStopに当たり、床の切り欠きから1階へ落下する。開口は柱を避けて壁に設け、落下先から迷路へ復帰できる。 |

上階ゴール前の空き区画には、石色の腰壁と上部壁を組み合わせた仕切りを追加しています。`z=20.5` の横壁、`(22,21)` の通路止め、`x=21.5` の北側仕切りが徒歩の直進・横抜けを防ぎ、上記3回のSpin移動を経てゴールへ迂回する構成です。壁の上下には見通し用の隙間を残しています。入口脇の仕切りはStart `(19,19)` から東へ歩いてSpinを迂回する経路を塞ぎます。

停止後に次のStartまで歩く必要があり、自動で回り続けるループではありません。青いStartの床面矢印は移動方向を表します。水平Startの判定は水平方向に1m角で、高さ3mです。上下移動のStartは1m角です。移動区間にStart判定は延長していません。水平Spinでは進行前に横方向をStartの中心線へ合わせます。

1階からの上昇では、2階の穴の上方 `y=5` にStopを置き、停止後は北（+Z）の床へ移動しながら着地します。Stopへの接触はアバターの大きさによって中心より手前で起こるため、床面より十分上に配置しています。

各区間の通行・復帰と歩行による抜け道は、半径0.3m・高さ1.6mの仮想カプセルによるUnity上の近似で確認しています。アバターの大きさや姿勢によっては開口を通れる可能性があります。ジャンプ、移動速度や通信遅延を含めたCluster実機確認は未実施であり、到達制約や復帰の確実性は保証されません。
